# 만트라 반복 재생기 — 설계 문서

작성일: 2026-10-27

## 1. 목적과 배경

사용자는 카카오톡으로 받은 만트라 동영상이나 음악 파일을 스마트폰에서 **정해진 횟수만큼 반복 재생**하고 싶어 한다. 일반 플레이어의 "반복"은 횟수를 세 주지 않는다. 이 프로그램은 횟수를 세어 화면에 보여 주고, 마지막 회차가 시작될 때와 모두 끝났을 때 소리로 알려 준다. 그래서 사용자는 화면을 보지 않고도 수행을 이어 갈 수 있다.

## 2. 목표

- 휴대폰에 있는 동영상과 음악 파일을 N회 반복 재생하고 횟수를 센다.
- 반복 횟수는 기본 버튼 3·9·11·27·54·108, **직접 입력**, **무한 반복** 중에서 고른다.
- 재생 중에는 현재 회차와 목표(예: `37 / 108`, 무한일 때는 `37 / ∞`)와 **경과시간**을 화면에 표시한다.
- 표시 위치는 좌측상단, 우측상단, 좌측하단, 우측하단 중 하나를 사용자가 고른다.
- **마지막 회차가 시작될 때** 알림음을 울린다.
- **모두 끝나면** 완료 알림음(마지막 회차 알림음과 다른 소리)을 울리고 결과 화면을 보여 준다.
- **안드로이드(크롬)**에서는 화면이 꺼져도 재생과 횟수 세기, 알림음이 끝까지 이어져야 한다. 이 프로그램의 핵심 요구사항이다.
- 아이폰에서도 동작은 해야 한다. 다만 화면이 꺼지면 재생이 멈추는 것은 감수한다.
- **내 목록과 즐겨찾기:** 한 번 추가한 파일은 목록에 남아 다음부터 파일을 다시 찾지 않고 바로 재생한다. 자주 쓰는 파일은 즐겨찾기(★)로 맨 위에 모은다.

사용 환경: 안드로이드 크롬에서 연다(카톡 인앱 브라우저는 대상이 아니다). 범용 서비스가 아니라 사용자 주변의 몇 사람만 쓴다.

## 3. 하지 않는 것

- 앱스토어 앱(네이티브 앱)으로 만들지 않는다.
- 파일을 서버에 올리거나 공유하지 않는다. 계정이나 로그인도 없다.
- 재생 목록(여러 파일 연속 재생), 수행 기록과 통계 누적은 하지 않는다.
- 아이폰에서 화면이 꺼진 뒤의 재생은 보장하지 않는다.
- **카톡 폴더 자동 검색은 하지 않는다.** 웹페이지는 휴대폰 폴더를 직접 볼 수 없다. 파일은 안드로이드 파일 선택 창에서 사용자가 고른다. 안드로이드 앱으로 만드는 방안도 검토했지만, 사용자가 웹을 선택했다.
- **크롬 데이터 삭제 대비는 하지 않는다.** 크롬에서 사이트 데이터를 지우면 목록과 즐겨찾기도 지워진다. 사용자가 이를 감수하기로 했다. 백업과 복원 기능은 만들지 않는다.

## 4. 실패로 보는 경우 (동작은 하더라도)

- 안드로이드에서 화면을 끄면 재생이 멈추거나, 횟수가 실제 재생 횟수와 어긋나는 경우.
- 횟수를 잘못 세는 경우(건너뛰거나 두 번 세는 경우). 수행 횟수가 이 프로그램의 존재 이유다.
- 화면이 꺼진 상태에서 마지막 회차 알림음이나 완료 알림음이 울리지 않는 경우.

## 5. 화면과 흐름 (사용자 결정: B안, 설정 화면 → 재생 화면)

### 5.0 내 목록 (첫 화면)
- **＋ 파일 추가** 버튼: 안드로이드 파일 선택 창을 연다(동영상과 음성, 여러 개 선택 가능). 고른 파일은 **프로그램의 저장 공간에 복사**되어 목록에 남는다. 원본은 건드리지 않는다.
- 버튼 근처에 짧은 안내를 둔다: "카톡에서 받은 파일은 보통 `Movies/KakaoTalk`(동영상) 또는 `Download/KakaoTalk`(음성·기타)에 있어요. 카톡에서 먼저 '저장'을 눌러 주세요."
- 목록의 각 항목: 동영상/음성 아이콘, 파일 이름, 길이, ★ 즐겨찾기 토글, 삭제. 삭제할 때는 확인을 한 번 받는다.
- (2026-10-27 사용자 피드백으로 추가) 각 항목 아래에 그 파일의 현재 설정 한 줄 요약(예: `108회 · ↗ · 🔔 마지막 ON · 완료 ON`, 설정 전이면 "반복 횟수·알림음을 아직 정하지 않았어요")과 **⚙ 횟수·소리 설정** 버튼을 보여 준다.
- 즐겨찾기 항목이 맨 위에 모이고, 그 아래에 나머지가 최근 추가순으로 놓인다.
- **항목을 누르면** 그 파일이 선택된 설정 화면(5.1)으로 간다. **즐겨찾기 항목의 ▶ 바로 재생**을 누르면, 그 파일에 마지막으로 썼던 설정(횟수, 표시 위치, 알림음)으로 설정 화면을 건너뛰고 곧바로 재생한다. 단, 한 번도 설정한 적 없는 파일이면 기본값으로 시작하지 않고 설정 화면을 연다(사용자 피드백). — *파일별 설정 기억은 내 판단*
- 목록이 비어 있으면 파일 추가 안내만 크게 보여 준다.

### 5.1 설정 화면
- 제목, 고른 파일 이름, 그리고 목록으로 돌아가는 버튼.
- **반복 횟수:** 3 · 9 · 11 · 27 · 54 · 108 · 직접 입력 · ∞ (하나만 선택). 직접 입력은 1 이상의 정수만 받는다.
- **표시 위치:** ↖ ↗ ↙ ↘ (하나만 선택).
- **알림음 (사용자 요청):** `마지막 회차 알림음`, `완료 알림음` 켜기/끄기 스위치 두 개. 각각 따로 켜고 끈다. 처음 쓸 때는 둘 다 켜져 있다(기본값은 내 판단).
- **▶ 시작** 버튼.

### 5.2 재생 화면
- 영상이 화면 가득 나온다(비율 유지, 남는 부분은 검은색). 음악 파일이면 검은 화면 가운데에 파일 이름을 보여 준다.
- 고른 모서리에 반투명 배지로 `현재회차 / 목표`와 경과시간 `mm:ss`(1시간을 넘으면 `h:mm:ss`)를 표시한다.
- 화면을 탭하면 **일시정지/재개**와 **정지** 버튼이 몇 초 동안 나타난다.

### 5.3 결과 화면
- `108회 완료`(중간에 정지했으면 `37회 재생`), 걸린 시간.
- **다시 하기**(같은 파일과 설정으로 바로 다시 시작), **처음으로**(설정 화면).

## 6. 동작 규칙

- **회차 세기:** 시작하면 1회차다. 파일 하나가 끝까지 재생될 때마다 다음 회차로 넘어간다. 화면에 보이는 숫자는 "지금 재생 중인 회차"다.
- **마지막 회차 알림음:** 목표가 N일 때 N회차 재생이 시작되는 순간 한 번 울린다. 만트라 소리 위에 겹쳐 울린다. N=1이면 시작할 때 울린다. 무한 반복일 때는 울리지 않는다.
- **완료:** N회차가 끝나면 완료 알림음을 울리고 결과 화면으로 넘어간다.
- **무한 반복:** 마지막 회차 알림음과 완료가 없다. 정지를 누를 때까지 계속 재생한다.
- **정지:** 무한 반복이든 아니든, 정지를 누르면 그때까지의 결과 화면을 보여 준다(완료 알림음은 울리지 않는다). 결과의 횟수는 끝까지 재생한 회차 수로 센다. — *빌더 판단 사항: 진행 중이던 회차를 셀지 말지*
- **경과시간:** 시작한 순간부터 센다. 일시정지하는 동안에는 멈춘다.
- **알림음 끄기:** 스위치가 꺼진 알림음은 울리지 않는다. 완료 알림음을 꺼도 결과 화면은 똑같이 나온다.
- **설정 기억:** 횟수(직접 입력 값 포함), 표시 위치, 알림음 두 개의 켜기/끄기 상태는 파일마다 마지막으로 쓴 값을 기억한다. 처음 재생하는 파일에는 가장 최근에 쓴 설정을 기본값으로 보여 준다.

## 7. 화면이 꺼졌을 때 (안드로이드 핵심 요구사항)

- 안드로이드 크롬은 탭이 백그라운드로 가거나 화면이 꺼지면 `<video>` 재생을 멈추지만, **오디오 재생은 이어 간다.**
- 방식(제가 정한 것, 검토 후 변경): **소리는 항상 `<audio>` 하나에서만 나온다.** 동영상 파일이면 `<video>`는 음소거한 채 그림만 보여 주고, 오디오의 재생 위치에 맞춰 동기화한다. 화면이 꺼져 영상이 멈춰도 소리를 넘겨줄 일이 없고, 화면이 다시 켜지면 영상을 오디오 위치로 맞춘다. 음악 파일은 `<audio>`만 쓴다.
- 회차 세기는 이 `<audio>`의 "끝남" 이벤트 하나로만 한다. 그래서 두 번 세거나 놓칠 위험이 없다. 반복 재생은 `loop` 속성이 아니라 끝남 이벤트에서 처음으로 되감아 다시 재생하는 방식으로 한다.
- 알림음 두 개는 **시작을 누를 때(사용자 터치 시점)** 미리 불러오고 재생 권한을 확보해 둔다. 그래야 화면이 꺼진 상태에서도 울린다.
- 미디어 세션 정보를 등록해 잠금 화면과 알림창에 제목(파일 이름), `37 / 108` 같은 진행 상황, 재생과 일시정지 버튼을 보여 준다.
- 화면이 켜져 있는 동안에는 화면 꺼짐 방지(Wake Lock)를 요청한다. 사용자가 직접 화면을 끄는 것은 막지 않는다.
- 이 부분은 브라우저 정책에 좌우되므로 **실제 안드로이드 기기에서 화면을 끈 채 끝까지 재생해 보는 시험**을 완료 조건에 넣는다.

## 8. 만드는 방법 (제가 정한 것)

- 빌드 도구 없이 HTML, CSS, JavaScript만 쓴 정적 웹페이지. 외부 라이브러리는 쓰지 않는다.
- 파일은 `<input type="file" accept="video/*,audio/*" multiple>`로 고른다. 고른 파일 자체는 OPFS(Origin Private File System)에 복사하고, 목록 정보(이름, 종류, 길이, 즐겨찾기, 파일별 설정, 추가 시각)는 IndexedDB에 저장한다. 재생할 때 저장한 파일을 꺼내 `URL.createObjectURL`로 재생한다. 파일은 휴대폰 밖으로 나가지 않는다. — *저장 방식 세부는 빌더 판단 가능(IndexedDB에 Blob으로 둬도 됨)*
- 첫 파일을 추가할 때 `navigator.storage.persist()`를 요청한다. 저장 공간이 부족할 때 브라우저가 목록을 자동으로 지우지 않게 하기 위해서다. 공간이 부족해 추가에 실패하면 알기 쉬운 문구로 알린다.
- 알림음은 저작권 문제가 없는 짧은 소리를 프로젝트에 직접 넣는다(직접 합성해 파일로 만들어도 된다). 마지막 회차용은 부드러운 종소리 한 번, 완료용은 그와 구별되는 소리.
- 저장소를 쓸 수 없는 환경(시크릿 모드 등)에서도 이번 한 번의 재생은 정상 동작해야 한다.
- 배포는 사용자의 GitHub 계정 `okyoung2`(https://github.com/okyoung2)에서 GitHub Pages로 한다. 프로젝트 폴더와 같은 이름인 `aviPlayCounter`로 넣는다. 예상 주소는 `https://okyoung2.github.io/aviPlayCounter/`이다. 하위 경로에서 열리므로 모든 경로는 상대 경로로 쓴다. 새 저장소로 만들지, 기존 저장소의 하위 폴더로 넣을지는 배포할 때 사용자에게 확인한다. 두 경우 모두 주소는 같다. GitHub Pages는 HTTPS로 제공된다. Wake Lock 등이 HTTPS를 요구한다. 휴대폰 홈 화면에 추가할 수 있게 웹 앱 매니페스트와 아이콘을 넣는다.
- 화면 글자는 한국어. 휴대폰 세로 화면을 우선으로 하되 가로 화면에서도 깨지지 않게 한다.

## 9. 빌더에게 맡기는 것

- 색상과 글꼴 같은 시각 디자인(차분하고 어두운 톤 권장, 배지는 영상 위에서도 잘 읽혀야 함).
- 컨트롤이 사라지기까지의 시간, 버튼 크기 같은 세부 수치.
- 코드 구조, 그리고 회차 세기 같은 핵심 로직의 테스트 방법.
- 정지 시 진행 중이던 회차를 결과에 셀지 여부(6절).

## 10. 완료 조건

- 파일을 추가하고 브라우저를 완전히 닫았다 다시 열어도 목록, 즐겨찾기, 파일별 설정이 그대로 남아 있다. 즐겨찾기의 ▶ 바로 재생이 저장된 설정으로 곧바로 시작된다.
- 6절의 규칙대로 횟수, 알림음, 결과가 동작한다(무한 반복 포함).
- 시험 기기: **갤럭시 퀀텀5 (SM-A556S)**, 크롬. 시험은 사용자가 직접 한다. 그래서 배포된 주소와 짧은 시험 순서표를 함께 전달한다. 삼성의 절전 기능("절전 앱", "백그라운드 사용 제한")이 크롬을 재우면 화면이 꺼진 동안 재생이 멈출 수 있다. 그렇게 되면 크롬을 예외로 두는 설정 방법을 안내 문구에 넣는다.
- 위 기기에서 3회 설정으로 시작한 뒤 화면을 끄고, 마지막 회차 알림음과 완료 알림음이 울리는지 확인한다. 화면을 켜면 결과 화면이나 정확한 횟수가 보여야 한다.
- 아이폰 사파리에서 화면을 켠 상태로 기본 동작을 확인한다.
